At a glance

Training vs. evaluation

Training picks are sampled from the router (last 10% of training). Eval picks are the router's argmax at every replan. Numbers under each bar are RGB · depth · flow in %.

Picked slot vs. decoded content

The router picks a slot (named rgb, depth or flow). Without stream identity a slot's name does not fix what it generates, so the decoded content can differ from the pick. "Decoded" applies each slot's measured content to the eval picks. Numbers are RGB · depth · flow in %.

Picks during training

Share of each training batch routed to each stream (rank 0, 32 samples per logged step), rolling mean over 500 steps. Shaded: the 2k-step warm-up, where picks are uniform and the router is not trained. Hover a panel for exact values.

LIBERO: picks by suite

Eval picks per task suite (40 tasks, 50 episodes each). The small number is the suite's success rate.

LIBERO-Plus: picks by perturbation

Eval picks per perturbation category (1,495 tasks, at most 5 per base task). If the router reacted to the perturbation, the rows would change across categories.

LIBERO: picks per task

How this was computed

  • Training: train/router_pick_{rgb,depth,flow} from each run's local wandb file, logged every 10 steps by rank 0 as the fraction of that step's batch routed to each stream. Warm-up steps (≤ 2,000) are excluded from the summary.
  • Evaluation: every Router selected active_future=… line in the eval worker logs, assigned to the task running on that worker at that time. Each replan counts once. Tasks run with a fixed stream are excluded.
  • Decoded content: picks × each slot's measured content (rows = slot, columns = content). "Measured" = decoded futures were checked for that model; "assumed" = same stream embedding as a checked model, not decoded separately. For the full-layout router without identity the flow slot's split comes from 27 windows and varies with the task phase, so its decoded mix is approximate.
  • "One-stream tasks": tasks where one stream gets more than 90% of the replans.
  • Training samples from the router's distribution; evaluation takes the most likely stream. The two can differ even for the same model.
